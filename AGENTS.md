# AGENTS.md

fastapi-fullauth is an async authentication and authorization library for FastAPI, published to PyPI. The package lives in `fastapi_fullauth/`; tests in `tests/`; the MkDocs site in `docs/`.

## Setup

```bash
uv sync --dev --all-extras
```

## Checks

Run all of these before proposing a change. CI runs the first four on every pull request; the strict docs build is not in CI, so it catches broken doc links only when run locally.

```bash
uv run ruff check .
uv run ruff format --check .
uv run mypy --strict fastapi_fullauth
uv run pytest
uv run mkdocs build --strict
```

CI tests Python 3.10 through 3.14. When a change touches typing behaviour, mock patch targets, or newer stdlib APIs, also run the affected tests on the floor version:

```bash
uv run --python 3.10 --isolated --all-extras --group dev pytest tests/<file>.py
```

## Architecture

Requests flow `routers/` -> `flows/` -> `core/` (tokens, crypto, blacklist) and `adapters/` (the storage seam), with `protection/` (lockout, rate limits, passkey challenges) alongside. `FullAuth` in `fullauth.py` wires them and binds itself to `app.state.fullauth`.

- Flows are framework-agnostic: they take an adapter and a token engine and raise library exceptions; routers translate those into HTTP responses.
- Adapters implement `AbstractUserAdapter` plus opt-in feature mixins (roles, permissions, OAuth, passkeys, sessions). Routers for features an adapter cannot serve are not mounted.
- User ids are pluggable (`UserSchema[int]`, `UserSchema[str]`, UUID by default). Convert token subjects with `adapter.parse_user_id()`, never `UUID(...)`.
- Failure modes are deliberate: the Redis token blacklist fails closed, the Redis rate limiter fails open. Keep anti-enumeration and timing defenses intact.

## Tests

- Adapter behaviour belongs in `tests/adapter_conformance.py`, which every adapter test module runs through a subclass. Add adapter-specific cases only to that adapter's module.
- `fastapi_fullauth.flows` re-exports functions named like their modules (`login`, `refresh`, ...). On Python 3.10 a string patch target such as `"fastapi_fullauth.flows.login.<name>"` resolves to the function, not the module; patch with `importlib.import_module(...)` and `patch.object` instead.
- Tortoise caches query executors per process by model and table name: a second model named `User` on the same table in another test module reuses the first module's columns. Give it a different table name.
- The SQLModel mixins can back only one concrete table per process, and `tests/conftest.py` already uses them.
- Beanie tests run on mongomock; `tests/test_beanie_adapter.py` holds the shim that makes `init_beanie` work, so Beanie integration tests go in that module.

## Documentation

- Update `docs/` alongside any change to public behaviour, and `skills/fastapi-fullauth/` when it changes how users integrate the library. The skill is for agents in projects that *use* the library, not guidance for working on this repository.
- `llms.txt` and `llms-full.txt` are generated by the MkDocs build; do not add them to `docs/`. New docs pages go in both `nav` and the `llmstxt` plugin `sections` in `mkdocs.yml`.
- Add user-facing changes to `CHANGELOG.md` under `## Unreleased` (`### Added`, `### Changed`, `### Security`). Release headings are `## X.Y.Z` with no date.

## Conventions

- Branches: `feat/`, `fix/`, `refactor/`, `docs/`, `chore/`. `main` is protected; changes land through pull requests.
- Commit messages: short imperative subject; the body explains why.
- Code: type annotations everywhere (`mypy --strict` must pass), small focused functions, comments only where the reason is not evident, security-relevant events logged through `logging.getLogger("fastapi_fullauth.<area>")`.
